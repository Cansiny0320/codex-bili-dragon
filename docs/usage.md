# 使用说明

## 命令

| 命令                               | 行为                                           |
| ---------------------------------- | ---------------------------------------------- |
| `pnpm start`                       | 启动单实例后台和本地管理页，默认端口 18841     |
| `pnpm doctor`                      | 检查 Node、Codex 登录、ffmpeg                  |
| `pnpm doctor:protocol`             | 另检查官方 app-server 动态工具协议；不调用模型 |
| `pnpm mcp`                         | 启动 stdio MCP，stdout 专用于协议              |
| `node dist/runtime/cli.js install` | 注册到 Codex 用户 MCP 配置；需要用户主动执行   |
| `pnpm package`                     | 打包构建产物到 `dist/`，检查发布文件清单       |

Windows 下优先自动发现 Codex 桌面版自带的运行时；其他平台使用 PATH 中的 `codex`。如需指定：

```powershell
$env:BILI_DRAGON_CODEX = 'C:\path\to\codex.exe'
$env:BILI_DRAGON_DATA = 'D:\private\bili-dragon-data'
$env:BILI_DRAGON_PORT = '18841'
$env:FFMPEG = 'C:\path\to\ffmpeg.exe'
pnpm start
```

macOS/Linux 使用相应的环境变量赋值语法。自动发现运行时、Windows 之外的兼容性以实际 `doctor:protocol` 和 CI 结果为准。

## 作息与会话

在「活动时间」分别设置每个窗口的开始、结束和活动机会数。结束时间小于等于开始时间表示跨午夜。时区使用 IANA 名称，如 `Asia/Shanghai`。每个起始日期最多消耗 3 次计划机会，随机跳过也计入；手动探索不计入计划次数。

计划持久保存。已过期的旧窗口不会集中补跑。后台对任务唯一键去重；重启时把未结束的任务标成 `needs-review`。同一专属会话按队列顺序处理任务。关闭开关后不会启动新的自主任务；“暂停运行”还会请求中断当前回合。已经送达 B 站的请求不能撤回。

修改模型配置后，请重启后台，让专属会话重新读取模型设置。人设、兴趣和发送开关通过工具实时读取。

## 消息与发送

评论首次开启只记录当前收件箱基线。私信、直播收到事件后先保存，再确认交付。每个消息通道独立退避；读取失败不推进已读游标。直播轮询会受到上游退避和 B 站接口延迟影响，不保证每条弹幕都即时可见。

主人身份使用 UID；昵称用于展示和评论 @。不要把主人 UID 填成机器人账号自身 UID。私信接收方固定为主人，发送前仍会验证互关关系。

陌生人回复先进入管理页草稿。点击“批准发送”时再次检查通道开关；对同一事件只允许一次发送尝试。分享、回复的失败或超时均保留账本，防止结果不明时重新发送。“关闭待办”只关闭任务，不清空发送账本，不触发重试。

分享评分范围为 0～20，默认 13 分。日上限最多 3；工具请求还沿用上游按小时/每天的总量、写入间隔、限流退避和未知结果保护。收到主人消息会记入本地反馈并影响沉默衰减；选题会排除已写入日记的视频。

## 工具和证据范围

| 工具            | 用途                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------- |
| `dragon_status` | 人设、兴趣、双日记、收件箱、任务和审核状态，不返回账号凭据                                                  |
| `dragon_read`   | `search`、`video`、`subtitles`、`comments`、`debrief`、`frames`、`feed`、`session`、`quota`、`live-history` |
| `dragon_diary`  | 本地保存公开/私密两本日记，使用稳定 ID 去重                                                                 |
| `dragon_reply`  | 只回复已核实的事件，由后端选择真实目标；陌生人形成草稿                                                      |
| `dragon_share`  | 按设置分享已读取内容的视频；由后端和上游共同检查限制                                                        |

这里的“公开日记”只是写给主人的版本，不等于发布到互联网。抽帧只代表若干采样画面，字幕只代表可获得的文字。视频无字幕、工具失败、只读评论时应明确说明，不声称完整观看。

## 常见问题

- **Codex 初始化失败**：先运行 `pnpm doctor:protocol`。旧的 npm CLI 可能无法读取新版桌面配置或不支持动态工具。通过 `BILI_DRAGON_CODEX` 选择兼容可执行文件。不要为此删除官方配置或复制登录令牌。
- **工作区路由发现超时**：本项目会清理父 Codex 聊天的路由环境变量。若仍有错误，检查官方客户端登录与网络，再运行体检。
- **登录失效或 B 站限制请求**：在管理页更新 Cookie 或等待限制解除。后台保留错误并退避，不绕过平台限制。
- **缺少 ffmpeg**：安装 ffmpeg 或设置 `FFMPEG` 绝对路径。字幕、评论等文字读取不依赖它。
- **端口被占用**：修改 `BILI_DRAGON_PORT`。所有端口仍只监听 `127.0.0.1`。
- **锁文件或 JSON 损坏**：先停止后台，备份 `data/` 后检查对应文件。不要直接删除发送账本来恢复额度。
- **停止与卸载**：在运行终端按 Ctrl+C。若注册过 MCP，用官方 `codex mcp remove codex-bili-dragon` 移除；数据会保留。插件渠道安装的版本通过同一渠道卸载。

管理页链接中的令牌保存在当前浏览器会话中。重启后台后请使用终端打印的新链接。管理页不需要对公网开放，也不支持通过反向代理发布。

## 源码与构建包

源码克隆后运行 `pnpm install --frozen-lockfile` 和 `pnpm build`；更新源码后也要重新构建。自有源码位于 `packages/runtime` 和 `apps/dashboard`，运行时使用 `dist/` 中的构建产物。

`pnpm package` 生成 `.tgz`，包含构建产物、上游工具和插件清单。解压后，在 `package/` 内执行 `npm install --omit=dev --ignore-scripts` 安装运行依赖，再运行 `node dist/runtime/cli.js start`。构建包不包含开发源码，不能在其中执行开发检查。

在普通 Codex 聊天中注册工具可执行 `node dist/runtime/cli.js install`。这会主动修改 Codex 用户 MCP 配置；日常启动和体检不会修改它。支持本地插件的客户端也可加载已构建且已安装依赖的项目目录。

## 管理页

首页展示运行状态、近期视频、日记与待审核消息；「观看记录」可搜索标题或 BV 并查看已保存的字幕和评论。旧数据没有正文缓存时会显示缺失说明，不重新请求视频。其余页面分别管理日记、审核、人设与兴趣、活动时间、权限和账号。

页面每 5 秒刷新后台状态。编辑配置期间保留未保存的输入；「保存更改」提交，「取消」恢复后台值。手机宽度下通过左上角按钮展开导航。
