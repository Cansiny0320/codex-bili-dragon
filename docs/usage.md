# 使用说明

## 安装与控制

先按 [安装指南](../INSTALL.md) 在 Codex 中安装预构建 ZIP。日常直接说「打开小白龙管理页」「启动小白龙」「暂停小白龙」或「停止小白龙后台」。安装引导通过 `dragon_open` 打开对话右侧管理页，另有全局侧边栏入口。首次安装自动活动、主动分享、评论与弹幕权限关闭；私信权限默认开启，单号模式不可用。

排查时，可在安装结果的 `installedPath` 下执行下列命令，`node` 使用安装时选定的可执行文件：

| 命令                                                     | 行为                                                     |
| -------------------------------------------------------- | -------------------------------------------------------- |
| `node dist/runtime/cli.js start`                         | 启动或复用共享后台，返回后可关闭终端                     |
| `node dist/runtime/cli.js status`                        | 只检查后台是否运行                                       |
| `node dist/runtime/cli.js pause`                         | 关闭自动活动并请求中断当前回合，管理页仍可用             |
| `node dist/runtime/cli.js stop`                          | 暂停活动并停止共享后台                                   |
| `node dist/runtime/cli.js doctor --protocol`             | 检查 Node、Codex 登录、动态工具协议与 ffmpeg；不调用模型 |
| `node dist/runtime/cli.js serve`                         | 前台运行独立网页管理页，默认端口 18841                   |
| `node dist/runtime/cli.js migrate-data <旧目录绝对路径>` | 复制旧数据到空目标，保留源文件                           |

`install` 只对已校验的原始预构建包执行；它通过官方 Codex 插件命令注册本项目的插件源，不再单独注册用户 MCP。MCP 进程关闭不停止后台，同一用户的多个管理页共享一个后台。安装不会创建开机自启或系统服务。

Windows 优先发现 Codex 桌面版自带的 CLI，其他平台使用 PATH 中的 `codex`。可用 `BILI_DRAGON_CODEX` 指定实际 CLI 绝对路径、`FFMPEG` 指定 ffmpeg。`BILI_DRAGON_PORT` 仅影响 `serve`；原生插件后台使用系统分配的本机端口。

## 视频画面依赖

安装、CLI 启动及首次抽帧会优先复用有效的显式 `FFMPEG`、插件缓存或系统版本。没有可用版本时，自动下载当前系统/架构的固定 FFmpeg 构建，校验 SHA-256、解压并执行版本检查，成功后才启用。依赖保存在数据目录的 `dependencies/ffmpeg`，不修改系统 PATH。

已配置 Windows、Linux、macOS 的 x64 / arm64 下载来源；本次实机验证为 Windows x64，其他平台仅通过选择与安装逻辑测试。macOS 构建要求 macOS 12 或更新版本。首次安装需要网络，缓存可用后无需重复下载。

## 数据目录

默认位置与插件缓存分离：

| 系统    | 路径                                                                                        |
| ------- | ------------------------------------------------------------------------------------------- |
| Windows | `%LOCALAPPDATA%/CodexBiliDragon/data`                                                       |
| macOS   | `~/Library/Application Support/CodexBiliDragon/data`                                        |
| Linux   | `$XDG_DATA_HOME/codex-bili-dragon/data`，未设置时为 `~/.local/share/codex-bili-dragon/data` |

Windows Store 安装的宿主可能将应用数据重定向到其 `LocalCache/Local`。自定义 `BILI_DRAGON_DATA` 必须是绝对路径；从 `data/` 旧目录迁移前先停止旧后台，向空目标执行 `migrate-data`，再启动。升级、卸载均保留数据，旧文件不会自动删除。

在「账号连接」使用 B 站 App 扫码并在手机确认；二维码过期后点击刷新。成功后首页和账号页显示头像、昵称和实际登录 UID，自动活动保持暂停。手动 Cookie 输入位于高级选项。

单号模式自动把登录账号作为主人，不必填写 UID 和昵称；不会给自己私信或主动分享，探索与双日记照常使用。双号模式由小白龙登录小号，单独填写主人 UID 与称呼。旧配置首次校验时会保留独立的主人，或把同号配置转成单号。切换模式、主人或登录账号会先暂停，作废旧待发任务、消息与草稿，保留历史记录和未确认的发送账本。

Cookie 保存在本机文件中，未使用系统钥匙串。不要分享 `credentials.json`、`connection.json` 或含令牌的网页链接。管理接口不回传凭据；MCP App 通过宿主工具桥连接，无需把本机令牌放入界面 URL。

## 作息与会话

在「活动时间」分别设置每个窗口的开始、结束和活动机会数。结束时间小于等于开始时间表示跨午夜。时区使用 IANA 名称，如 `Asia/Shanghai`。每个起始日期最多消耗 3 次计划机会，随机跳过也计入；手动探索不计入计划次数。

计划持久保存。已过期的旧窗口不会集中补跑。后台对任务唯一键去重；重启时把未结束的任务标成 `needs-review`。同一专属会话按队列顺序处理任务。关闭开关后不会启动新的自主任务；“让小白龙休息”还会请求中断当前回合。已经送达 B 站的请求不能撤回。

修改模型配置后，请重启后台，让专属会话重新读取模型设置。当前人设每轮注入，兴趣和发送开关通过工具实时读取。升级增加或调整业务工具时，会建立新的专属会话以注册完整工具；旧会话、日记和本地记录保留。

## 个性与探索

小白龙默认好奇、有自己的判断，直接说具体事情，日记可以短，不要求每次都有感悟或情绪变化。名字、自称、对你的称呼和性格正文都可以在「个性与兴趣」修改。升级只替换与旧默认完全相同的正文，自定义正文和空正文保留。

每轮先接上近期日记与反馈，在当前数量上限内初筛（默认 5 条），挑 2–3 条值得的内容深读；没有合适内容时不凑数。分享前比较候选，只考虑最值得的一条，也允许不分享。每个后台浏览任务最多一次分享尝试，失败后不能换视频继续发。

双日记正文分别写想和你聊的事与自己的想法。需要延续的偏好保存在独立备注：你明确说过的、暂时猜测的、它自己的兴趣及以后想看的方向。明确偏好保留主人文字来源；点赞只能支持猜测，没回复不代表不喜欢。这些备注不会改写管理页中的兴趣设置。

「操作权限 → 自动收藏」默认关闭。开启后，小白龙才会把实际读过、以后还想重看的内容加入登录账号的默认收藏夹；每天最多 3 条，同视频 30 天内不重复。同类已有两条时需要比较已有内容，不能只换个理由继续收。收藏失败或超时会保留未确认账本，不自动重试。

## 消息与发送

评论首次开启只记录当前收件箱基线。私信、直播收到事件后先保存，再确认交付。每个消息通道独立退避；读取失败不推进已读游标。直播轮询会受到上游退避和 B 站接口延迟影响，不保证每条弹幕都即时可见。

主人身份使用 UID；昵称用于展示和评论 @。双号模式的主人 UID 必须与登录账号不同。新配置默认开启私信权限，但单号不能向自身发送；私信接收方固定为双号模式的主人，发送前仍会验证互关关系。已保存的关闭选择不会被升级覆盖。

陌生人回复先进入管理页草稿。点击“批准发送”时再次检查通道开关；对同一事件只允许一次发送尝试。分享、回复的失败或超时均保留账本，防止结果不明时重新发送。“关闭待办”只关闭任务，不清空发送账本，不触发重试。

分享评分范围为 0～20，默认 13 分。日上限最多 3；工具请求还沿用上游按小时/每天的总量、写入间隔、限流退避和未知结果保护。收到主人消息会记入本地反馈并影响沉默衰减；选题会排除已写入日记的视频。

开启评论监听后，探索时会检查近 48 小时的评论回复与收到的赞；同一事件只记一次，不能靠重复读取刷新互动时间。昵称相同不算身份匹配。采集失败单独标为未知，暂缓主动分享，但仍可读内容、写日记。关闭评论监听不会为这项功能额外轮询评论或点赞。其他聊天软件中的互动不可见。

## 工具和证据范围

| 工具              | 用途                                                                                                        |
| ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `dragon_open`     | 打开 Codex 对话右侧管理页，只启动本地服务                                                                   |
| `dragon_control`  | 按用户要求启动、查状态、暂停或停止后台                                                                      |
| `dragon_status`   | 人设、兴趣、双日记、收件箱、任务和审核状态，不返回账号凭据                                                  |
| `dragon_read`     | `search`、`video`、`subtitles`、`comments`、`debrief`、`frames`、`feed`、`session`、`quota`、`live-history` |
| `dragon_diary`    | 本地保存公开/私密两本日记，使用稳定 ID 去重                                                                 |
| `dragon_reply`    | 只回复已核实的事件，由后端选择真实目标；陌生人形成草稿                                                      |
| `dragon_share`    | 按设置分享已读取内容的视频；由后端和上游共同检查限制                                                        |
| `dragon_feedback` | 读取真实主人反馈，按已启用范围刷新，复用近期结果并区分失败与空结果                                          |
| `dragon_favorite` | 按独立收藏权限保存已读取视频，检查同类比较、日限额与重复记录                                                |

配置、凭据和审核等 `dragon_admin_*` 工具仅向管理页开放；专属自主会话只有上述 7 个业务工具（不含 `dragon_open`、`dragon_control`），不包含审批工具。

这里的“公开日记”只是写给主人的版本，不等于发布到互联网。抽帧只代表若干采样画面，字幕只代表可获得的文字。视频无字幕、工具失败、只读评论时应明确说明，不声称完整观看。

## 常见问题

- **Codex 初始化失败**：先运行 `node dist/runtime/cli.js doctor --protocol`。旧的 npm CLI 可能无法读取新版桌面配置或不支持动态工具。通过 `BILI_DRAGON_CODEX` 选择兼容可执行文件。不要为此删除官方配置或复制登录令牌。
- **工作区路由发现超时**：本项目会清理父 Codex 聊天的路由环境变量。若仍有错误，检查官方客户端登录与网络，再运行体检。
- **登录失效或 B 站限制请求**：在管理页「账号连接」重新扫码，或在高级选项更新 Cookie；请求受限时等待限制解除。后台保留错误并退避，不绕过平台限制。
- **FFmpeg 下载失败**：安装、CLI 启动和首次抽帧会检查依赖。恢复网络后重试；也可用 `FFMPEG` 指定已有可执行文件的绝对路径。失败时不会替换已验证的旧版本。字幕、评论等文字读取不依赖 FFmpeg。
- **独立网页端口被占用**：使用 `serve` 时可修改 `BILI_DRAGON_PORT`。原生插件后台自动分配端口，均只监听 `127.0.0.1`。
- **锁文件或 JSON 损坏**：先停止后台，备份数据目录后检查对应文件。不要直接删除发送账本来恢复额度。
- **侧边栏未出现或仍是旧版**：先检查 `codex plugin list --marketplace bili-dragon --json` 中已安装、已启用；在插件详情页选择「管理 → 重新加载」，再打开管理页。不能以普通网页打开成功代替原生入口验证。
- **更新与卸载**：先执行 `stop`。更新时使用新预构建 ZIP 重走安装流程；卸载用 `codex plugin remove codex-bili-dragon@bili-dragon`，需要时再移除 `bili-dragon` 插件源。数据保留。旧版单独注册的 MCP 仅在确认不用后移除。

仅独立网页模式使用带令牌的链接，该链接中的令牌保存在当前浏览器会话中。重启后台后请使用终端打印的新链接。管理页不需要对公网开放，也不支持通过反向代理发布。

## 源码与构建包

源码克隆后运行 `pnpm install --frozen-lockfile` 和 `pnpm build`；更新源码后也要重新构建。自有源码位于 `packages/runtime` 和 `apps/dashboard`，运行时使用 `dist/` 中的构建产物。

`pnpm package` 生成 `dist/codex-bili-dragon-<version>-plugin.zip` 及 `.sha256`，包含自包含运行时、两种管理页、上游工具、依赖许可、安装引导与插件清单。用户解压后执行 `node dist/runtime/cli.js install`，无需安装 npm 依赖。安装器仅为该插件设置 Node 搜索路径，不修改全局 PATH。

`pnpm test:package` 将 ZIP 解压到仓库之外，验证没有 `node_modules` 时的 MCP、后台、9 个网页路由与停止流程。`pnpm test:ui` 分别验证网页管理页和 MCP App 桥接；宿主原生侧边栏仍需在实际 Codex 中核验。

`pnpm test:behavior` 使用当前已登录的 Codex 和固定视频、消息素材，检查实际文风、收到纠正后的选题与空候选行为；会消耗模型额度，不属于默认单元测试。所有 B 站读取和发送均由 fixture 替代，不接真实账号，结果保存在 `work/behavior-check-result.json`。测试结束后停止专属测试会话并清理隔离数据。

## 管理页

首页展示运行状态、近期视频、日记与待审核消息；「观看记录」可搜索标题或 BV，按时间行查看字幕、按列表查看评论，并显示真实抽帧图。只展示当时实际读到的字幕范围，不把前 160 行当成全片字幕。未读取、读取失败、缓存缺失和没有可用字幕分别显示。已有素材缺少标题或封面时，会通过视频元数据补全，不改变原记录时间。其余页面分别管理日记、审核、人设与兴趣、活动时间、权限和账号。

「行动记录」按时间查看搜索、素材读取、日记、分享、回复、收藏和任务起止，支持按类型与结果筛选、分页。新记录区分自主运行、管理页手动操作和聊天工具调用；私信与评论在发送前保存完整正文和目标，确认成功后标为已发送。超时或中断显示待核查，不自动重发。记录保存在本机 `activities.json`，完整历史不因界面分页而截断。

旧版本的操作、任务、日记与素材会按现有证据回填；没有来源就显示“来源未记录”，旧私信只保留片段时显示“历史正文不完整”。查看历史不会重新发送或重新抓取视频。

页面每 5 秒刷新后台状态。编辑配置期间保留未保存的输入；「保存更改」提交，「取消」恢复后台值。手机宽度下通过左上角按钮展开导航。
