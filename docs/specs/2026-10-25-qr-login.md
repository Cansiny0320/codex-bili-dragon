# 默认扫码登录

状态：用户已批准（2026-10-25）。

## 行为

- 账号连接页默认使用 B 站 App 扫码。已有有效连接显示账号昵称、UID、头像和重新登录操作。
- 手动 Cookie 输入与获取说明收进高级选项，保留原来的三个凭据字段和本地存储格式。
- 展示等待扫码、等待手机确认、成功、过期和网络失败；过期或失败可重新获取二维码。离开账号页停止轮询并取消当前尝试。
- 本地后台负责请求 B 站、解析登录 Cookie、校验账号及保存凭据。页面只收到二维码、随机会话句柄和公开账号信息。
- 登录失败、取消或过期不覆盖现有凭据。成功替换凭据前暂停活动；数据、权限和主人 UID 保持原值，活动由用户主动重新启用。
- 同时只保留一次登录尝试。刷新二维码、取消及手动保存使旧尝试失效；迟到响应不能覆盖更新后的登录。
- 不新增网站账号、云端凭据托管、自动续期或账号模式。真实扫码由用户在手机完成。

## 接入

- 复用现有 worker、HTTP / oRPC 和 MCP App 桥，不新增服务。登录会话为每个 worker 内存中的共享实例，不能按请求创建。
- 增加生成、轮询、取消三个管理页专用操作；检查登录返回结构化公开账号状态。模型可用工具不增加凭据接口。
- 固定 HTTPS 地址：B 站 passport 的 web/qrcode/generate 与 web/qrcode/poll；缺少 buvid3 时调用 finger/spi；成功后调用 web-interface/nav 校验账号。
- 只从 Set-Cookie 提取白名单凭据，不使用回跳 URL 携带的认证参数。二维码在本地编码，不经过第三方图片服务。
- 轮询间隔至少 2 秒，合并并发请求，会话最多 3 分钟；请求设超时，异常信息不包含响应正文、登录 URL 或凭据。
- 参考用户指定会话「推敲在线养鱼产品与双模式商业方案」中已落地的接口和 Cookie 处理；只读取其 owning source，不修改其他项目。

## 验收

离线测试覆盖各状态、过期、重复请求、取消与迟到响应、保存失败保留旧凭据、凭据不泄露；HTTP/MCP 两条路径一致。无桌面输入的浏览器检查覆盖默认扫码、手机确认、成功账号、刷新和高级 Cookie 表单。构建、项目检查、安装包独立运行检查通过后更新本地插件；通过插件菜单重新加载，不重启 Codex。
