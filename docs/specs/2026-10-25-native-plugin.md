# Codex 原生插件安装与管理

## 已批准目标

用户批准将项目交付为完整的本地 Codex 插件：在 Codex 中一句话安装、启动，在侧边栏和聊天右侧管理，保留已有八页界面、作息和受控互动。用户明确不需要 npm 包分发。

## 方案

- 分发预构建的插件 ZIP，包含 Skill、本地 MCP、管理页、第三方工具和运行依赖。安装端无需 pnpm、编译或 npm install。
- 安装指南供 Codex 执行；安装器使用 Codex 官方 marketplace/plugin 命令注册独立本地插件源，保留其他插件与设置。Node 可使用本机或 Codex 提供的运行环境，安装时固定实际可用路径；不依赖写死的某个用户路径。
- 增加 onboarding Skill，检测 Codex 登录和服务状态，引导在管理页填写 B 站凭据。凭据不得进入聊天、工具结果或安装包。
- 现有 React 页面增加标准 MCP Apps 运行入口和工具传输层。注册独立的 global 与 thread 入口，保持原有网页入口可用。
- MCP 连接使用同一个后台服务。启动、暂停、停止可由插件控制；关闭管理面板不停止已启动的后台，不创建系统服务或开机启动项。首次安装保持自动活动和外部写入关闭。
- 模型可见工具保留原有行为，另提供打开管理页与后台控制。账号设置、配置和审核接口仅面向 App，不加入自主运行会话的工具集。
- 使用插件缓存之外的固定数据目录；旧版项目 data 可显式迁移，原数据保留。安装与升级不能把用户数据写进发布包或覆盖现有数据。
- 首版按本地桌面插件交付。官方商城的本地 MCP 白名单不作为完成安装体验的前提。

## 验收

1. 在干净目录解压安装包后，使用可用 Node 与 Codex 即可安装，包内依赖完整。
2. 插件可被 Codex 发现并启用；MCP 握手、工具发现、后台启动和停止成功。
3. global/thread 入口声明有效，App 的资源读取、初始化、页面导航和读写操作通过标准桥接完成。
4. 多个 MCP 连接共用后台；退出页面不重复创建服务；停止和崩溃恢复不重试结果不明的发送。
5. 八个页面继续工作，设置持久化；凭据不回显，模型不能自行审核草稿。
6. 重复安装和升级保留数据与其他插件。安装流程没有 npm 发布或 npm 包依赖安装步骤。

## 授权与验证边界

本次授权包括本地实现、安装本项目插件、启动默认暂停的服务和相关非破坏性验证。真实 B 站发送和模型生成不用于自动测试。提交、推送、GitHub Release 上传和商城发布需要对应的明确授权，在本地结果可审阅后再处理。
