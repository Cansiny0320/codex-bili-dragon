# 自动更新

用户已批准：兼容更新自动切换后台；工具接口、连接层或数据格式不兼容时提示重新加载插件。

## 行为

- 默认关闭，在账号设置中开启。后台启动和每六小时检查官方 GitHub 最新稳定 Release，不检查预发布版本，不注册或替换插件市场。
- 下载版本化 ZIP 和 SHA-256，验证归档、逐文件清单及兼容清单，安装到数据目录下独立的不可变版本目录。
- MCP 连接保持运行，每次调用重新发现兼容后台；请求发送后失败不自动重试。重新打开管理页读取新资源，已打开的旧页面可能需要重新打开。
- 停止接收新定时任务及启动新监听，等待当前任务、监听和 HTTP 请求结束。忙碌或存在无法确认的切换条件时延期，不中断发送。
- 独立切换进程在旧后台退出后启动新后台；新后台通过运行状态和只读业务检查后才恢复任务。失败回退旧程序，配置、日记、队列和发送台账始终使用原数据，不恢复旧副本。
- 更新不改变活动、分享、监听权限。关闭自动更新取消尚未开始切换的更新。工具定义、桥接代码或持久化数据合同不兼容时显示“需要重新加载插件”，由用户在 Codex 中更新、重新加载。
- 首次使用必须手动安装包含本功能的版本。运行后台版本与 Codex 插件版本可能不同。

## 兼容边界

构建生成兼容清单：桥接源文件、工具描述与 schema、管理接口与配置合同、依赖锁定和持久化合同版本。只有全部一致才自动切换。后台业务实现、提示词及管理页面可以兼容更新。修改持久化语义时必须提升数据合同版本；无法证明兼容则走手动更新。

## 验收

用隔离数据目录和本地假 Release 验证真实子进程切换、多客户端重连、业务响应变化、故障回退、不重复发送和配置保留；拒绝损坏、越界及不兼容归档。验证开关、状态和旧页面重开行为。不得访问真实 B 站账户、启用生产自动活动或自动发布。
