# 媒体依赖自动安装与视频信息修复

用户在本次会话明确选择「安装时自动下载对应平台依赖」，并要求按正常使用流程实测。采用该方案，不把大体积二进制直接嵌入插件 ZIP。

## 行为

- 插件安装命令自动发现已有可用 FFmpeg；缺失时按 OS 与架构下载固定版本的 LGPL 构建，校验固定 SHA-256，解压并验证可执行文件后才完成安装。安装位置是插件私有数据目录，不修改系统 PATH、不要求管理员权限。
- Windows / Linux 覆盖 x64、arm64，使用 BtbN 的月末保留版本；macOS 覆盖 x64、arm64，使用附带对应源码与构建信息的 LGPL 发布物。保留包内许可、动态库和构建信息。各平台清单明确来源、摘要和最低系统要求。
- 下载到临时目录，成功后原子落位；失败保留原有可用版本，提供可重试的错误；再次安装复用已经验证的依赖。显式 FFMPEG 设置继续优先。启动命令也准备依赖，抽帧路径可为旧安装补齐依赖。
- 视频元数据通过现有只读 video 命令增加的结构化模式取得，与字幕、评论是否可读分离。封面 HTTP / 协议相对地址规范为 HTTPS，仅使用 B 站图片域名。失败不丢弃已经取得的素材。启动后补全旧记录，保留原探索时间与已读动作。

## 压力测试与边界

已通过 brainstorming / grill-with-docs 检查：不能固定为开发机的二进制；不能依赖浮动 latest URL；下载失败或内容损坏不能当作安装成功；不能丢掉动态库、许可及旧账号数据；不能把读取元数据算作读过视频内容。安装不改变 B 站操作权限。

Windows 本机验证实际下载、缓存复用、启动、抽帧；其他平台验证选择与解包逻辑，并明确未做原生执行验证。用户准许真实私信和公开评论测试，私信对象为已配置主人，评论限定 BV1Bx411B78v；未提供直播间时不实际发送直播弹幕。通过 UI 配置、探索、监听、审核等产品路径触发，不伪造收件事件或绕过发送守卫。

## 回滚

停止新后台、重新安装旧插件，并保留数据备份；新增依赖目录与元数据字段不改变凭据。临时测试开关在结束后恢复。无 Git 提交、推送或远端发布。
