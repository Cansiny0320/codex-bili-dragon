# 组件、状态管理与公开分发

用户于 2026-10-25 批准：使用 shadcn/ui base-nova 与 Zustand，不加入暂时用不到的技术；完成 Release + GitHub 市场、更新 README，检查后 push 并发布。

## 范围

- 管理页使用官方 base-nova 组件源码及可识别的 components.json。只引入当前界面用到的组件；保留页面布局、蓝色主题、数据与操作权限，移除覆盖组件本身行为和尺寸的全局 CSS。
- Zustand 管理后台快照、请求状态、通知及设置草稿。每个管理页实例拥有独立 store；React Context 仅传递 store，SSR 不创建全局用户状态。瞬时页面选择、搜索、二维码状态可保留组件本地状态。
- HTTP 与 MCP App 使用相同状态逻辑。轮询不覆盖未保存的草稿，保存失败保留输入；取消回到最新后台配置。异步过期响应与卸载后响应不可污染新状态，发送操作不能因重复点击重复执行。
- GitHub 的 main 保留源码；marketplace 分支包含目录清单和完整预构建插件。市场标识继续使用 bili-dragon，插件标识不变。公开市场无需用户编译，但本地 MCP 仍需要兼容 Node。ZIP 安装器继续可选择 Codex 自带 Node，作为安装入口与兼容方案。
- 首个公开版本使用 0.7.0。Release 附 plugin.zip、SHA-256 和准确说明。README 分别说明加入 GitHub 市场与下载 ZIP，不声称进入官方公共目录。

## 压力测试结论

- 单独增加市场清单会失败：源码分支不含 dist/runtime 与管理页。发布源必须由验证过的包生成，且不包含私密数据和开发依赖。
- 本地 MCP 依赖 Node，不能把目录下载成功等同于服务可运行。分别验证市场清单解析、安装路径、MCP 工具及 UI；无 Node 的环境走安装指南的运行环境检查。
- Zustand 的模块级 singleton 会导致 SSR/不同管理页串状态，采用作用域 store。异步刷新与设置提交存在竞态，需要单测覆盖。
- 组件迁移会改变原生控件语义；检查标签关联、Tab 键、Tabs 键盘切换、复选框与折叠区域，以及桌面/窄屏布局。
- base-nova 的图标占位符在导入时按现有 Lucide 依赖转换；复用现有 cn，不引入同名 npm 包或整套无用组件。
